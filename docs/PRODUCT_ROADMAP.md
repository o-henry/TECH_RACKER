# Product roadmap

이 문서는 기술 추적 사이트의 다음 기능 후보를 우선순위와 데이터 원칙에 따라 정리합니다. 새 기능도 원출처 사실, 미확인 값과 편집 판정을 분리해야 합니다.

## P0 — source diff

검증 실행 사이에 어떤 문장, 수치, 단계, 날짜와 출처가 바뀌었는지 기술별로 보여 줍니다.

- 새 원출처, 수정된 원출처와 철회된 원출처를 구분합니다.
- 사건 발생일, 게시일, 사이트 반영일을 별도 필드로 유지합니다.
- 상태가 바뀐 이유와 상태를 유지한 이유를 모두 기록합니다.
- 사용자는 한 시간 동안의 새 자료가 실제 판정을 바꿨는지 즉시 확인할 수 있습니다.

## P0 — milestone watchlist

기술별 다음 확인 지점을 개인 감시 목록으로 저장하고, 공식 결과가 게시된 경우에만 알립니다.

- 임상 결과, 규제 결정, 생산 시작, 운영 수치와 논문 게재를 서로 다른 이벤트로 분류합니다.
- 뉴스 기사는 신호로만 사용하고 최종 알림은 원문 확인 뒤 보냅니다.
- 동일 사건의 중복 기사와 기업 홍보성 반복 게시를 묶습니다.

## P0 — coverage heatmap

분야와 기술별 데이터 부족 영역을 시각화합니다.

- 논문, 임상, 규제, 공시, 생산, 운영, 안전성, 비용, 접근성의 근거 유무를 표시합니다.
- 기술 수가 적은 분야와 원출처가 한 기관에 편중된 분야를 구분합니다.
- “자료 없음”과 “조사하지 않음”을 구분해 자동 수집 우선순위를 만듭니다.

## P1 — evidence conflict detector

서로 다른 원출처의 수치·단계·날짜가 충돌할 때 상태를 자동 확정하지 않고 검토 대기열로 보냅니다.

- 사건 발생일과 게시일의 혼동을 탐지합니다.
- 기업 주장, 규제기관 판정과 동료평가 결과를 별도 증거 등급으로 유지합니다.
- 단위, 모집단, 평가변수와 비교 기준이 다른 수치의 단순 비교를 막습니다.

## P1 — relationship path explainer

관계 지도에서 두 기술 사이의 연결 경로와 각 연결의 근거를 단계별로 설명합니다.

- 직접 기술 의존, 공통 제조·운영 시스템과 추론 연결을 구분합니다.
- 성과 전이가 가능한지, 불가능한지와 추가 검증 조건을 보여 줍니다.
- 연결이 약해지거나 제거된 경우에도 변경 이유를 남깁니다.

## P1 — maturity gate timeline

각 기술의 다음 발전 단계를 성능 하나가 아닌 통과 관문으로 표현합니다.

- 과학 검증, 재현, 안전성, 규제, 제조, 비용, 유지보수와 접근성 관문을 사용합니다.
- 통과, 진행 중, 미확인과 실패를 구분합니다.
- 예상 날짜 대신 공식 확인 지점과 무효화 조건을 우선 표시합니다.

## P2 — private research dossiers

소유자가 기술별 메모, 조사 질문과 추가 원출처를 저장하는 비공개 작업 공간입니다.

- 사이트의 검증 사실과 개인 메모를 시각적으로 분리합니다.
- 메모 내용은 자동으로 공개 사실이나 관계로 승격되지 않습니다.
- 원출처가 확인된 항목만 검토를 거쳐 편집 데이터에 반영합니다.

## P2 — export and reproducibility

선택한 기술의 사실, 출처, 관계, 병목과 다음 확인 지점을 JSON·CSV·Markdown으로 내보냅니다.

- 스냅샷 날짜와 소스 버전을 포함합니다.
- 미확인 값과 편집 판정을 객관적 사실과 분리해 내보냅니다.
- 재현 가능한 인용 링크와 기술 ID를 유지합니다.
